## Document Purpose

## 核心实体

| 实体 | 是什么 | 存在哪 | 谁产生 |
|---|---|---|---|
| **工作单元** | 一次搜索查询（一个关键词片段）→ 一份排序结果集 | `src/` | 用户通过 CLI 触发 |
| **交付物** | `42find` 二进制可执行文件 | `src/42find-cli/` 编译输出 | `cargo build --release` |
| **真相源** | 本地文件系统——磁盘上的文件就是事实，索引只是缓存 | 用户机器 | 用户自己维护 |
| **搜索索引** | 加速全文检索的结构，可从文件重建 | `_build/` 或系统临时目录 | `42find-core` 构建 |

**「工作单元」是最要紧的一行**——它是这个系统的分形：一件做通了，一百件就是重复它。
它怎么算合格，见 `intent.md` 的「作品区」小节——**判据只有一份**。

## 作品区实体（src/）

| 目录 | 是什么 | 谁产生 | 谁是谁的输入 |
|---|---|---|---|
| `src/42find-core/` | 核心库 crate：索引构建、查询引擎、多格式文本提取 | AI + 人协作编写 | 无外部 crate 依赖（纯库）；为 `42find-cli` 提供 API |
| `src/42find-cli/` | 命令行入口 crate：参数解析、结果渲染、用户交互 | AI + 人协作编写 | 输入：用户命令行参数；依赖 `42find-core` 提供的搜索 API |

## 参与者

| | 负责 | 不负责 |
|---|---|---|
| **人** | 意图的源头 · 挑错 · 定标 · 最终拍板 | 不做能被规则判对错的检查 |
| **AI** | 源头之后的一切：整理 / 生成 / 检查 | 不定方向、不定标准 |

## 关键关系

- **谁是谁的输入**：`42find-core` 的搜索 API 是 `42find-cli` 的唯一输入；用户文件系统是 `42find-core` 的原料
- **谁定谁的标准**：`intent.md` 里"top-3 + 2 秒"是唯一合格判据，`42find-core` 的每次改动都对着它量
- **什么一变、什么就得跟着变**：文件格式扩展（新增 PDF/Word 支持）→ `42find-core` 的解析层变 → CLI 的输出格式可能随之变

> **真相是角色，不是属性**——磁盘文件在用户机器上是原件；索引在 `_build/` 里是派生物，随时可丢可重建。
